## Goal

Build the production stroke engine that both devices and the exporter use, so wet ink, dry ink and exports never differ.

## Steps

If the dated D6 entry chose Jetpack Ink instead of the core engine, stop. Report what this task should become.

1. Promote the T0.10 algorithm into `core/crates/vw-ink` with `algorithm_version = 1`:
   - brush families pen, marker, highlighter (flat ends; multiply blending happens in the renderer) and vector_eraser (geometry for hit testing);
   - pressure curve: a monotonic cubic Bézier;
   - stabilization 0–1, and smoothing.
2. Incremental builder API: `begin(brush)` → `append(samples)` returns the changed geometry range → `finish()` returns the final geometry; `cancel()`.
3. Determinism: f64 and `libm` only; no platform-dependent float functions. Output quantized to 1/256 px and hashed.
4. Golden tests: commit the geometry hash for every fixture trace. Run them on Windows and on the phone (`hil-test rust vw-ink`); the hashes must match.
5. Incremental output must equal the final geometry exactly (no wet-to-dry pop).
6. Hit testing: stroke bounds, and distance to stroke for the object eraser and selection.
7. Benchmark: append cost per sample, target < 20 µs p95 on the phone.
