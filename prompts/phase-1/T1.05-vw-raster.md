## Goal

Exports that are byte-identical whichever device produces them, at source resolution, with honest metadata and preflight — plus the text layout both apps draw with.

## Steps

1. `core/crates/vw-raster` renders every annotation kind on the CPU with tiny-skia:
   - Build tiny-skia without its `simd` feature, or prove byte-identical output on x86-64 and arm64 before committing goldens; record which.
   - Strokes from vw-ink geometry; shapes; arrows with heads; numbered markers.
   - Text with bundled fonts (Inter, Noto Sans, Noto Sans Mono; SIL OFL is fine to bundle) and deterministic layout through a permissively licensed shaping/layout crate (record why). Expose the layout and glyph outlines so the apps draw text from exactly the same layout (T1.08b).
2. Input decoding:
   - PNG, JPEG and WebP via permissively licensed Rust decoders;
   - apply EXIF orientation into document space; extract ICC profiles;
   - HEIC is out of scope here (OS decoders come in Phase 2).
3. Exports:
   - clean full image; clean region at source resolution; marked full; marked region;
   - formats: PNG (8- and 16-bit), JPEG (quality setting), WebP (lossless and lossy);
   - metadata in each file: revision `r{seq}-{hash8}`, source asset hash, export settings (PNG iTXt; JPEG and WebP XMP);
   - import → export → import round trips are lossless for alpha and 16-bit PNG (FORMAT-005).
4. Preflight:
   - WebP ≤ 16,383 px per side; JPEG ≤ 65,535; a memory-estimate guard;
   - on failure, return typed errors that name the alternatives (PNG, split, tiles);
   - never scale silently.
5. Color: clean exports keep the original ICC profile. The "AI/chat" variant converts to sRGB with a permissively licensed color-management library (check the license) and records the conversion.
6. Golden tests:
   - byte-exact PNG outputs for a fixture set, on Windows and on the phone (`hil-test rust vw-raster`);
   - clean exports pixel-equal to the source (hash) for unmodified regions.
