## Goal

Secure, revocable pairing — by QR code or by a short code that can't be brute-forced — with keys kept at app level, plus discovery and route safety.

## Steps

1. Device identity: long-term key pairs and self-signed certificates (check the license of any crate you use, for example rcgen).
2. App-level trust store: a `TrustStore` interface in vw-net (keys, pinned certificates, paired and revoked times) with
   - a Windows implementation that protects its file with DPAPI (CryptProtectData, current-user scope) under `%LOCALAPPDATA%\Visual Workbench\trust\`;
   - an in-memory implementation for tests;
   - a UniFFI callback interface the Android app implements with a Keystore-wrapped key in T1.10.
   Nothing from the trust store ever goes into a project folder, a `.vwbz` export or a log.
3. QR pairing: payload {PC DeviceId, certificate SHA-256, endpoints, 128-bit secret, expiry}; TLS 1.3 with a custom verifier pinning the PC certificate; proof = HMAC-SHA256(secret, TLS exporter value with label "EXPORTER-vw-pairing"); single use; 5-minute expiry; both sides pin each other's certificates.
4. Code pairing (fallback): the PC shows an 8-digit code; the phone connects without a pin, then runs a PAKE (SPAKE2 or CPace) whose transcript is bound to the TLS exporter, so no value derived from the code is sent before the key exchange. `spake2` 0.5.0-pre is a preview, so use the latest stable 0.4.x or a stable CPace crate; record which and why. On success both sides show the PC fingerprint for confirmation, then pin. Codes are single-use and expire after 5 minutes; pairing locks for 10 minutes after 5 failed attempts.
5. Revocation from either side; unknown and revoked peers are refused at handshake.
6. Discovery: advertise `_vworkbench._udp` with TXT {id = DiscoveryId (random, regenerated at each start, unrelated to DeviceId), v = protocol major} only. Expose an interface so the Android app can use NsdManager instead.
7. Route safety (Windows): detect a tether interface that became the default route; expose the finding, the metric-fix command (admin) and its revert as an API for the desktop app.
8. `tools/pair-cli` (add to the workspace): a PC console tool plus an adb-pushed phone binary that pair over tethering (the QR payload is passed as a file for the test), exchange ops, revoke, and confirm refusal. T1.09 uses the phone binary to test the PC app's pairing screen.
9. Windows Firewall: explain to Christian, then (with his approval of the admin prompt) add temporary inbound allow rules for the executable under test, limited to the local subnet, for example `New-NetFirewallRule -DisplayName "VW dev <task>" -Direction Inbound -Action Allow -Program <full path to the exe> -Protocol UDP -RemoteAddress LocalSubnet -Profile Any` and the same for TCP. If Windows already created a Block rule for that executable, delete it. Never conclude that a carrier fails until a firewall block has been ruled out. Remove the rules at the end of the task.
10. Tests: expired secret; reused secret; replayed proof; wrong code 5 times → lockout; revoked peer refused; TXT contents; a scan proving no key material lands in a project folder or `.vwbz` export.
