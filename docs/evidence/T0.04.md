## Implementation

- Separate Kotlin Android diagnostic application at tools/pen-trace/probe-android.
  It records every pointer and historical frame, axes 0–63, pressure/size,
  tilt/orientation/distance, actions, flags, buttons, source, numeric runtime
  device ID, key events and declared axis ranges. Nanoseconds are used on API 34+;
  API 30 timestamps are explicitly labelled as millisecond resolution.
- Recorder with named recording tasks, unique app-private JSON files, a 30,000
  sample/event bound and explicit background/overflow interruption markers.
  Saved recordings remain on the phone; collection writes ignored private files
  for inspection before public fixture publication. No real owner handwriting
  was collected during this run.
- Eight declarative Samsung RemoteAction mappings, F1–F8, without the proprietary
  SDK. Click/double click, four swipes and both circles have distinct mappings.
- AndroidX Graphics front-buffer diagnostic drawing and CPU draw/Choreographer
  callback timings. They are estimates, not compositor presentation or photon
  measurements. Rendering continues with recording off for the thermal session.
- Instrumentation uses UiAutomation injection and an independent recording of
  received events. It checks sample count, axes, tools, actions, button state,
  cancellation, source/modifiers, key delivery and rebased timestamp error.
  Original and replay JSON, plus maximum/p95 errors, are collected privately.
- Strict host validation, observed pressure/rate/axis summaries, a 24-category
  S23 provenance gate, and bounded temperature sampling every 30 seconds.
- build.ps1 build-pen-probe and hil-test pen / pen-owner; test/lint and actual
  runtime-license graph coverage include the new module.

The operator guide is tools/pen-trace/README.md. The owner recording directory
contains a README only; no generated event stream is labelled an owner fixture.

## Platform limits and retained failures

Android's public MotionEvent construction accepts milliseconds. Replay uses one
uptime shift and nearest-millisecond rounding, then reports received timestamp
error after subtracting that shift. Injection submission scheduling error is a
separate metric. Original nanosecond precision is retained in owner JSON.
Device IDs and framework flags can be rewritten by Android; numeric device ID
is retained as provenance, not forged. Cancellation semantics are asserted.
Nonzero classification cannot be synthesized across the supported API range.

The public API exposes actionButton only for reading. Nonzero actionButton and
classification values fail replay explicitly before injection. This may affect
Samsung button-transition traces and needs a measured platform decision; no
requirement was relaxed and no hidden API/root access was introduced.

The first compile rejected an attempted actionButton assignment. The code now
checks the public API limit. The first physical replay then delivered 8/8 motion
samples and 16/16 key events with zero timestamp error, but failed seven Y-axis
comparisons: status text reflow moved the canvas by 53 pixels after the first
event. A fixed-height status area resolves the layout cause. The failed run and
its private data were retained, not overwritten. Its maximum injection lateness
was 3 ms; this is synthetic test scheduling evidence only.

The initial expanded license run failed because the host checker still expected
four runtime configurations. Both the graph and checker now require all six;
the complete 181-module census passed. Exact Graphics Core 1.0.4 POM license:
Apache-2.0. A preliminary PowerShell POM reader needed byte-to-text handling;
the downloaded XML/POM was then inspected directly.
