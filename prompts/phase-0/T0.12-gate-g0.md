## Rules

- **Scope:** do only this task. Don't start other tasks, refactor unrelated code, or change requirements you weren't asked to touch.
- **Licenses:** nothing the app ships or links may be GPL, AGPL, SSPL, non-commercial or of unknown license. LGPL is allowed only as a dynamically linked, replaceable library on Windows. The only other exceptions are the documented ones in BUILD_SPECIFICATION §2.5. Check every new dependency's license before adding it. Reading GPL source for ideas is fine; never copy or translate it.
- **Secrets:** never write API keys, pairing secrets, private keys, tokens or signing keys into the repository, logs, evidence files, screenshots or commit messages, and never ask Christian to paste a key or password into this chat. Keys live in Windows Credential Manager or the Android Keystore.
- **Evidence privacy:** before committing any screenshot, recording or log, crop it to the window under test and remove QR codes, IP and MAC addresses, device serial numbers, user names, chat content and notifications. Once T0.03 has built it, take screenshots with `tools/diag-win --screenshot` (Per-Monitor-V2 aware) and record the display scale.
- **Truthfulness:** report something as working only if you ran it and recorded the result. Emulators and simulators do not count for pen, capture, injection, driver, codec or latency checks. Say plainly what you could not test.
- **Spec conflicts:** if the spec is wrong for this hardware or platform, don't quietly change the requirement. Record the evidence in this task's evidence file, propose an alternative, and report it.
- **Versions:** check the official release page before choosing a version; use stable releases only (no previews, betas or release candidates unless this task says so); pin exact versions and record them in docs/TOOLCHAIN.md.
- **Keep the laptop usable:** it has 16 GB RAM and 4 cores. Cap Gradle at `-Xmx3g`, don't run heavy builds in parallel, and stop processes you start.
- **Scripts:** run PowerShell scripts as `powershell -NoProfile -ExecutionPolicy Bypass -File <script>`; never change the machine-wide execution policy.
- **Windows code** must be Per-Monitor-V2 DPI aware and use physical pixels for capture, UI Automation and input math.
- **Rust:** edition 2024; rustfmt; clippy with `-D warnings`. No `unwrap`, `expect` or `panic` in library code (use `thiserror`). `unsafe` only in FFI and platform modules, each block with a SAFETY comment. Workspace crates use `publish = false` and `license = "LicenseRef-VisualWorkbench-Proprietary"`.
- **Kotlin:** official style; explicit API mode in shared modules; coroutines for async work; nothing blocking on the main thread.
- **Tests** live next to the code. Hardware tests are clearly marked and run through the `hil-test` entry point once it exists; Rust tests run on the phone with `hil-test rust <crate>`.
- **Git:** follow docs/IMPLEMENTATION_PLAN.md "Automatic phase publishing" and AGENTS.md. Inspect status and preserve unrelated changes. Start from main with validated dependency work integrated; use the task branch convention and conventional local commits. Local commits/completed dependency integration and phase-end commit/push to origin/main are already owner-authorized; do not request Git approval again. Push automatically at numbered phase conclusions, not after every task. Scan the exact staged bytes, exclude secrets/local artifacts/verification images, use normal non-force pushes and verify remote SHA parity. Product gate confirmation remains separate. Use worktrees for parallel tasks and take turns on the shared phone.
