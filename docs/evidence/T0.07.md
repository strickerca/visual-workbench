## Failures retained and corrected

- Initial WGC polling treated a null empty-pool interface as a failure. Windows
  documents null for no frame; pinned windows-core maps it to Error::empty with
  HRESULT zero. The bounded poll now handles that representation. The failed run
  and its numeric report remain, and generated media was disposed.
- A multi-profile full run completed both HEVC profiles then crashed with
  `c0000005`. Windows Application event 1000 names `IntelControlLib.dll_unloaded`,
  offset `000000000004b06a`. It has no completed aggregate report. Each profile
  now runs in a separate bounded process with incremental result persistence.
  This isolates diagnostic work; it does not establish long-running driver safety.
- The first Android report stopped at render timestamp validation. A subsequent
  smoke accounted for all 22 input/output/Surface callbacks in each profile and
  retained native timestamps predating queueing. Boolean output release used
  media-relative PTS as the Surface timestamp. Final code explicitly supplies
  System.nanoTime, retains callback delivery separately, and never treats an
  invalid native delta as latency evidence.
- Two native lint findings and Android nullable video-capability compile errors
  were fixed. A parser fixture's 15-second PowerShell startup timeout fired under
  build load; its finite limit is now 60 seconds inside the process-tree runner.
  All failures have retained text logs; reruns are separate attempts.
