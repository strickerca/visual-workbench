## Goal

Implement the coordinate-space module every other component uses, with property tests strong enough that nobody has to doubt the math again.

## Steps

1. In `core/crates/vw-geom`, implement:
   - Point and Rect (f64).
   - Affine: 3×3 with a, b, c, d, e, f; composition; inverse returning a typed error when singular.
   - Camera {center in D, scale, rotation} → view matrix.
   - ScreenTransform (display rotation plus insets).
   - LensTransform, with latch and unlatch semantics.
   - ExifOrientation: all 8 variants, R↔D.
   - PdfPage: crop box and /Rotate → D (y-down).
   - SvgViewport.
   - CaptureGeometry: client rectangle in host space, DPI scale, geometry revision → F↔H integer mapping.
   - Pixel snapping: edges to integers, points to pixel centers.
2. All math in f64 using `libm` for cross-platform determinism. Errors via `thiserror`; no panics.
3. Property tests (proptest, ≥ 10,000 cases each):
   - D→V→P→V→D round trip ≤ 1e-6 px for scales 1/64–64 at any rotation;
   - EXIF orientations: R→D→R is the identity;
   - F→H exact with negative origins and DPI scales 1.0–3.0;
   - snapping is idempotent;
   - lens latch: samples during a stroke always map through the latched transform.
4. Benchmarks (criterion): transform cost per point must be negligible (target < 50 ns).
5. Rustdoc on every public item, quoting the space definitions from the spec.
6. Run the tests on `x86_64-pc-windows-msvc`, and on the phone with `hil-test rust vw-geom`. Record both results.
