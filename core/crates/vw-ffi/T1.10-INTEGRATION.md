## Contracts implemented

- `projectRole` verifies the session-service installation identity against the
  project's persisted local identity and reports its authoritative host. It does
  not migrate project authority or assume every PC-local project is host-owned.
- `inspectQr` uses the native expiring QR decoder and validates numeric private,
  loopback, or link-local endpoints. `joinQr` independently checks exact endpoint
  membership. Shared text uses canonical unpadded base64url under `vw-pair:v1:`;
  raw QR payloads remain bounded to 4 KiB and secret-bearing. Do not log or persist
  QR text. Pairing endpoints and live session endpoints remain distinct.
- Discovery retains at most 64 untrusted entries for 60 seconds. Each service
  owns one bounded worker (at most four services), two queued calls, and reserved
  shutdown. Windows mDNS runs only on selected interfaces; snapshot browsing is
  capped at 500 ms and existing 256-event bound. IPv6 scoped endpoints select the
  exact IPv6 interface index. Browse-only mode registers no fake listener.
  Android uses the same catalog with platform-owned NsdManager registration and
  resolution; platform listeners must stop before releasing their facade.
- An advertisement uses one actual listener port and only rotating `id`/protocol
  `v` TXT properties. Do not combine independently assigned carrier ports.
  Desktop browse-only mode requires selected numeric local addresses; Android's
  platform catalog may start with an empty address list. Numeric address
  enumeration offers candidates only, capped at 256 interfaces/addresses and
  two concurrent enumeration workers. It never chooses an adapter or carrier.
- `tetherRouteWarnings` reads Windows default routes for an explicitly selected
  interface and returns risk/fix/revert command text. No elevation, PowerShell,
  adapter/firewall setting, or automatic correction occurs. Apps must query on
  each tether connection/reconnect. Non-Windows calls fail explicitly.
- The client sends one durable pending transaction at a time. The host validates
  a candidate without accepting it, requests only its declared missing immutable
  originals, verifies streamed BLAKE3/size, persists bytes, and only then commits
  metadata/ack. Actual commit revalidates after I/O. A client serves pending
  originals only when named by its project's durable outbox. Scratch remains
  private; partial transfer resumes across carrier reconnect. A process restart
  restarts a partial download; it retains the source outbox/original and cannot
  falsely acknowledge acceptance. Per-original transfer bound remains 64 MiB.
- Typed `NewObjectPreview` supports line, arrow, rectangle, ellipse and text.
  Object/document/layer/author/creation time and shape kind stay bound to the
  reliable lifecycle-v2 opening. Valid bounded geometry, style and transform may
  change; this preserves ordinary D-space tool widths. Changed identity/kind is
  refused. New previews never mutate the project, and final Create uses the same
  gesture/object identity. Large text/polyline previews can exceed the datagram
  budget and fail admission; final reliable edits remain independent. One
  gesture still has one target; multi-selection previews remain commit-only.
- `original_upload_v1` and `new_shape_preview_v1` capabilities prevent an older
  app adapter from silently using incompatible blob/shape behavior. Missing
  required capabilities expose upgrade-required status.

## Written regression coverage

noncanonical/oversize rejection, service/project identity mismatch, read-only
author-bound transaction preflight, phone MP4 original upload before host
acceptance with offline undo/reopen/reconnect/redo, and new-shape geometry updates
with forged-author/layer/kind rejection and delayed-packet retirement. The MP4
fixture establishes container/byte-transfer behavior only, not playback.
An additional synthetic loopback test creates native identities, a QR offer and
an eight-digit code only in fixture app trust. It scans both synchronized project
trees, a real `.vwbz` export, and the archive's validated extracted members for
fixture private-key DER/serialized bytes, QR secret/payload and code bytes.
Assertions never print those credentials. This is a written test, not a passed
secret-scan receipt or proof about untested app/platform persistence.

These tests have not been executed by this author. UI integration, generated
binding compatibility, latency, Windows/Android discovery, QR scanning,
Keystore, physical carrier switching, adb watching/reverse recreation, metrics
actions, phone-origin authority migration, all-app workflows, and screenshots
retain their separate software/device/manual acceptance requirements.
