## Goal

Create a code skeleton for every component so the whole repository builds, add one-command entry points (including running Rust tests on the phone), and add the license gate and the secrets-and-identifiers scan that every later task relies on.

## Steps

1. Root Cargo workspace with members `core/crates/*` and `host-win/crates/*`, using the crate names from the plan's repository layout. Rust tools that later tasks create under `tools/<name>` are added to `members` explicitly by those tasks. Each crate is a compiling stub with a `lib.rs` and one test, `publish = false` and `license = "LicenseRef-VisualWorkbench-Proprietary"`; don't choose an open-source license without asking Christian. The host-win crates compile to empty stubs on non-Windows targets via `cfg`.
2. Gradle multi-project under `apps/`: `shared` (Kotlin Multiplatform with commonMain, androidMain and desktopMain), `android` (application), and `desktop` (Compose Multiplatform desktop). Put pinned versions in `gradle/libs.versions.toml`.
3. Gradle tasks that build the Rust core for real: cargo-ndk for Android (output into jniLibs) and cargo for Windows (DLL copied to desktop resources). Even with stub crates, prove the pipeline end to end.
4. Entry points, as a `justfile` or `build.ps1`: `build-core`, `build-android`, `build-desktop`, `test-all`, `lint-all`, `license-check` and `hil-test`. Every `build-*` runs `license-check` first. Every entry point returns non-zero on failure. If you use `just`, add `set windows-shell := ["powershell.exe", "-NoProfile", "-ExecutionPolicy", "Bypass", "-Command"]` (just's default shell, `sh`, isn't on Windows).
5. `hil-test`:
   - The default form checks that exactly one authorized adb device is present (print its model, never its serial), installs the APK and runs the instrumentation tests (stubs for now).
   - `hil-test rust <crate>` builds the crate's tests for arm64 with `cargo ndk -t arm64-v8a test --no-run`, pushes the test binaries and the crate's fixtures to `/data/local/tmp/vw-tests/`, runs them with `adb shell`, and returns their exit codes. Also register it as `CARGO_TARGET_AARCH64_LINUX_ANDROID_RUNNER` so `cargo test --target aarch64-linux-android` works. Prove it with one stub crate's test.
6. License gate for Rust (`deny.toml`):
   - Allow MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, Unicode-3.0, Unicode-DFS-2016, CC0-1.0, MPL-2.0, BSL-1.0 and OFL-1.1 (fonts). Set `[licenses.private] ignore = true` for the workspace's own crates.
   - Deny GPL, AGPL, LGPL and unknown licenses. Add exceptions only as BUILD_SPECIFICATION §2.5 lists them; none apply to Rust crates yet.
7. License gate for Gradle: add a license-report plugin whose own license is permissive (verify it) and an allowed-licenses check that fails the build. Record that JNA is used under its Apache-2.0 option.
8. `third_party/LICENSES`: a manifest (file path → license → SHA-256) for bundled binaries that cargo-deny and Gradle can't see, plus a check in `license-check` that every file under `third_party/` (except the manifest) is listed with a matching hash. It is empty for now.
9. Prove the gates on a throwaway branch: add a GPL-licensed crate and a GPL-licensed Maven artifact, show that `license-check` fails and that `build-core` and `build-android` fail too, then delete the branch.
10. Secrets and identifiers scan: add a permissively licensed scanner (for example gitleaks, MIT — verify) to `lint-all`, covering the repository and docs/evidence/. Add rules for IP and MAC addresses and adb-serial-like strings in docs/evidence/, and a placeholder rule for the MCP token (its format is defined in T2.09). Allowlist 64-hex-character digests (BLAKE3, SHA-256) by path; never disable rules globally.
11. Requirement-ID checks:
    - Generate `docs/v1_requirement_ids.txt` — the 98 IDs in docs/REQUIREMENTS.json whose `v1_note` does not start with "new".
    - Add a check to `lint-all` that every ID in that file still exists in REQUIREMENTS.json (QUALITY-007).
    - Add `python tools/check_plan_coverage.py` (already in the package) to `lint-all`.
12. Write a short root `README.md` section on building (keep the package README's content) and a `CLAUDE.md` with the conventions from docs/IMPLEMENTATION_PLAN.md "Conventions" and the rules below. In CLAUDE.md, write the branch rule generically as `task/<task-id>-<slug>`.

## Rules

- **Scope:** do only this task. Don't start other tasks, refactor unrelated code, or change requirements you weren't asked to touch.
- **Licenses:** nothing the app ships or links may be GPL, AGPL, SSPL, non-commercial or of unknown license. LGPL is allowed only as a dynamically linked, replaceable library on Windows. The only other exceptions are the documented ones in BUILD_SPECIFICATION §2.5. Check every new dependency's license before adding it. Reading GPL source for ideas is fine; never copy or translate it.
- **Secrets:** never write API keys, pairing secrets, private keys, tokens or signing keys into the repository, logs, evidence files, screenshots or commit messages, and never ask Christian to paste a key or password into this chat. Keys live in Windows Credential Manager or the Android Keystore.
- **Evidence privacy:** before committing any screenshot, recording or log, crop it to the window under test and remove QR codes, IP and MAC addresses, device serial numbers, user names, chat content and notifications. Once T0.03 has built it, take screenshots with `tools/diag-win --screenshot` (Per-Monitor-V2 aware) and record the display scale.
- **Truthfulness:** report something as working only if you ran it and recorded the result. Emulators and simulators do not count for pen, capture, injection, driver, codec or latency checks. Say plainly what you could not test.
- **Spec conflicts:** if the spec is wrong for this hardware or platform, don't quietly change the requirement. Record the evidence in this task's evidence file, propose an alternative, and report it.
- **Versions:** check the official release page before choosing a version; use stable releases only (no previews, betas or release candidates unless this task says so); pin exact versions and record them in docs/TOOLCHAIN.md.
- **Keep the laptop usable:** it has 16 GB RAM and 4 cores. Cap Gradle at `-Xmx3g`, don't run heavy builds in parallel, and stop processes you start.
- **Scripts:** run PowerShell scripts as `powershell -NoProfile -ExecutionPolicy Bypass -File <script>`; never change the machine-wide execution policy.
- **Windows code** must be Per-Monitor-V2 DPI aware and use physical pixels for capture, UI Automation and input math.
- **Rust:** edition 2024; rustfmt; clippy with `-D warnings`. No `unwrap`, `expect` or `panic` in library code (use `thiserror`). `unsafe` only in FFI and platform modules, each block with a SAFETY comment. Workspace crates use `publish = false` and `license = "LicenseRef-VisualWorkbench-Proprietary"`.
- **Kotlin:** official style; explicit API mode in shared modules; coroutines for async work; nothing blocking on the main thread.
- **Tests** live next to the code. Hardware tests are clearly marked and run through the `hil-test` entry point once it exists; Rust tests run on the phone with `hil-test rust <crate>`.
- **Git:** follow docs/IMPLEMENTATION_PLAN.md "Automatic phase publishing" and AGENTS.md. Inspect status and preserve unrelated changes. Start from main with validated dependency work integrated; use the task branch convention and conventional local commits. Local commits/completed dependency integration and phase-end commit/push to origin/main are already owner-authorized; do not request Git approval again. Push automatically at numbered phase conclusions, not after every task. Scan the exact staged bytes, exclude secrets/local artifacts/verification images, use normal non-force pushes and verify remote SHA parity. Product gate confirmation remains separate. Use worktrees for parallel tasks and take turns on the shared phone.
- **Christian's help:** when you need him (physical pen actions, approving an admin prompt, installing an app, entering a key, changing a phone setting), batch the requests into numbered, plain-language steps and wait for him to confirm.
