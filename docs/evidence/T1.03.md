## Persistence and recovery

`contracts/storage.sql` is schema 2 and remains the fresh-database source of truth.
Numbered migrations 001/002 reproduce exactly the same SQLite objects. Schema 1
was an unshipped draft; synthetic fixtures provide the original host identity and
revision-zero snapshot needed to preserve undo/retry semantics. Incomplete,
corrupt or unknown drafts fail without committing a partial schema upgrade.

Projects use caller-selected folders with `project.sqlite`, `blobs/aa/bb/<hash>`
and `cache/`. SQLite 3.53.2 is bundled through pinned rusqlite/libsqlite3-sys.
Runtime pragmas are WAL, synchronous=NORMAL, foreign_keys=ON and trusted_schema=OFF.
A process-owned advisory lock serializes writers. An acceptance appends its exact
transaction/ack, current lookup rows, conflict records and any due checkpoint in
one SQLite transaction; only then is the in-memory host installed. A failure
preserves the old host and retry identity. Originals are never deleted by commits,
undo, migrations, cache eviction or archive operations.

Checkpoints occur every 500 accepted transactions or 300,000 ms at a commit;
`snapshot_now` supports an application's idle/save timer. Loading validates the
latest checkpoint, scans retained log bindings and replays only its tail. A 503-edit
test restores from sequence 500 with exactly three replayed transactions. Sequencing
checkpoints retain revision hashes, exact retries, receipt times, inverse journals,
write ownership, conflict bindings, tombstones and committed/cancelled gestures.
Historical operations are not re-executed before the chosen snapshot. Current
project payloads are limited to 64 MiB and host checkpoints to 256 MiB; decoding,
SQLite column bounds and schema-shape checks reject malformed input explicitly.

Offline queue entries retain exact bytes and stable local order. Reused IDs with
changed bytes fail. Queue payloads bind to their SQL metadata on reopen. Original
asset metadata is retained for accepted history and pending AddAsset transactions,
so exporting an offline project includes originals needed by its queued work.
Capture session/geometry/platform metadata, including full uint64 frame IDs, round
trip. Frame IDs use decimal TEXT to avoid signed SQLite integer truncation. Current
lookup rows are checked against independently regenerated projections; altered
schemas, triggers, metadata, logs and checkpoints fail closed. Device rows contain
opaque IDs, labels, platform and Lamport counters, with no pairing credentials.

## Blobs, caches and portable archives

Blobs stream through bounded buffers into temporary files, are flushed, then
published without overwriting existing content. Reads verify the full BLAKE3 hash.
Existing symlinks, junctions, corrupt originals and non-file targets are rejected.
File contents are flushed on both platforms; directory fsync is additionally used
on Android/Unix. Filesystem checks assume the application owns its project tree;
they do not establish a sandbox against concurrent privileged directory replacement.

The RAM API accounts bytes globally and per named cache, returns LRU victims and
provides defaults of 256 MiB on phone and 512 MiB on desktop. Payload owners must
release returned victims when wired into the applications. Disk cache eviction is
restricted to verified manifest-listed entries under its dedicated cache directory;
unknown files and every original remain untouched. Reserve uses decimal bytes:
max(5,000,000,000, min(total / 20, 10,000,000,000)). Low space returns a clear error.
A free-space interface permits exact boundary and changing-capacity tests; the
production implementation queries the actual filesystem. Final cache verification
also covers space consumed during publication rather than only its initial estimate.

`.vwbz` export takes a VACUUM INTO copy, clears device labels and vacuums again so
old labels do not remain in free pages. It exports verified immutable inventory,
including historical and pending assets, and excludes cache/locks/WAL sidecars.
Import checks bounded ZIP/ZIP64 metadata before allocation, exact member names,
duplicates, file types, sizes, CRC and BLAKE3. Stored-size inconsistencies, traversal,
symlinks, missing/extraneous blobs and excessive metadata fail before publication.
Import validates in a sibling staging directory, closes SQLite handles, then uses
a no-replace directory rename. Existing destinations are preserved.

The project-owned 2,816-byte MP4 contains 30 synthetic 64x64 H.264 gray frames over
1,000 ms. Windows Media Foundation generated it, then a separate decoder confirmed
all 30 frames. Both platforms store/read/archive the same bytes and BLAKE3:
`b491e1e9ef1c7a62611e895878799dbff1e8f61a389ab5df7d65ac979b3ec40c`.
It is a retained synthetic test fixture with provenance, not a verification capture.
