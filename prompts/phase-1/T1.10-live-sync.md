## Goal

Pair the phone app with the PC, then make edits flow live between them — including strokes still being drawn, cancellations, reconnects and offline work — without ever duplicating or losing anything, and without developer mode.

## Steps

1. Phone pairing screen (replacing the T1.08a placeholder):
   - QR scanning with CameraX + ZXing core (both Apache-2.0; not ML Kit), asking for the CAMERA permission when the screen opens;
   - 8-digit code entry as the fallback, with fingerprint confirmation;
   - the Android trust-store implementation (keys wrapped by an Android Keystore key);
   - NsdManager discovery;
   - the paired-devices list and revoke.
2. Pair the phone with the PC app (Christian scans the QR code). Connect sessions using the carrier order from the dated D7 entry.
3. Gesture streaming:
   - The phone sends GestureUpdate messages (≤ 120 Hz, batched sample deltas) on EPHEMERAL.
   - The PC renders provisional geometry with the same vw-ink engine.
   - The commit carries the gesture_id, so provisional swaps to committed without a flash.
   - A cancel (palm, ACTION_CANCEL, app backgrounded) sends GestureCancel, and the PC removes the provisional stroke within one frame.
   - Handle drags and slider moves stream the same way (GestureUpdate kinds HANDLE_DRAG and SLIDER), so the peer shows intermediate states, not only the final one.
4. Edits made on the PC with the mouse (T1.09) appear on the phone the same way. Every tool's objects render identically on both devices (EDIT-001), and move/resize works from either device (EDIT-004).
5. Reconnect mechanics (§4.6):
   - The desktop app watches `adb devices` and re-creates `adb reverse` within 1 s of the phone reappearing.
   - When the tether link drops, the phone shows a one-tap shortcut to the tethering settings (Android leaves tethering off after a replug).
   - Status words follow §4.17 and §4.18: RECONNECTING, then SYNCED — or OFFLINE (n pending) if the link stays down.
   - Pending OPS resync with no duplicates; EPHEMERAL is cleared.
   - Route safety: on every tether connection the desktop app calls the T1.06b route-safety API; if the tether became the default route, it shows the §4.6 warning with the one-click metric fix (admin) and its revert. Test it once and record interface names and metrics before and after (no addresses).
6. Offline work and conflicts (SYNC-001): with both devices showing the same objects, disconnect the phone (airplane mode and unplug the cable). On the phone, change the color of one object; on the PC, change the color of the same object; then reconnect. The edits sync, the §4.4 rule picks the winner, and exactly one `conflicts` row records the losing value.
7. CONNECT-001: revoke the pairing; Christian turns Developer options off on the phone; pair again and edit over USB tethering. adb is unavailable during this test, so observe from the PC app and ask Christian what the phone shows. Then he turns Developer options and USB debugging back on and re-accepts the adb prompt.
8. CONNECT-002: with the router's internet (WAN) cable unplugged by Christian, revoke, pair again and edit over Wi-Fi.
9. PERF-002: echo-based timing with a clock-offset estimate. Record p50/p95 over USB and over Wi-Fi.
10. Camera independence (CORE-002): 100 random PC edits leave the phone camera bit-identical, and the other way round.
11. Run scenarios A02 and A06 on hardware (skip steps marked "From Phase 2" or later; those are re-runs at later gates). Record the phone with `adb shell screenrecord`; ask Christian to record the PC window (Snipping Tool → Record, or Win+Alt+R). Apply the evidence privacy rules to both recordings.
12. Windows Firewall: explain to Christian, then (with his approval of the admin prompt) add temporary inbound allow rules for the executable under test, limited to the local subnet, for example `New-NetFirewallRule -DisplayName "VW dev <task>" -Direction Inbound -Action Allow -Program <full path to the exe> -Protocol UDP -RemoteAddress LocalSubnet -Profile Any` and the same for TCP. If Windows already created a Block rule for that executable, delete it. Never conclude that a carrier fails until a firewall block has been ruled out. Remove these development rules at the end of the task; T1.12 adds the permanent rule for the installed app.
13. Security check (CONNECT-003): confirm the phone's trust list is wrapped by its Keystore key, and scan a project folder and a `.vwbz` export from each device for key material.
14. Status words (UX-005): screenshot SYNCED, SYNCING, RECONNECTING and OFFLINE (n pending) on both devices as they occur (EXPORT READY is checked in T1.11).
