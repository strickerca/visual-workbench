## Goal

Build the shared test-fixture set without bloating the repository, and measure big-image handling on both devices.

## Steps

1. Create `fixtures/` with `images/`, `pdf/`, `svg/` and `malformed/`, and a README listing every file's provenance, license and SHA-256. Use only files you generate or that are permissively licensed; no copyrighted images. `fixtures-private/` (Christian's own photos) and `fixtures/generated/` are git-ignored.
2. Generators, not big files: write committed generator scripts with fixed seeds (Python or Rust) and commit a SHA-256 list of their outputs. Outputs over 10 MB go to `fixtures/generated/`; never commit a file over 10 MB. Generate:
   - a synthetic 16320×12240 JPEG (noise, gradients and text; quality 95);
   - a 12 MP synthetic set;
   - a 1440×20000 synthetic long screenshot.
3. HEIF: a small Android helper (or the T0.04 probe, extended) that writes a synthetic 200 MP HEIF with androidx.heifwriter (Apache-2.0) from a generated pattern; pull it into `fixtures/generated/`. Also ask Christian for one real 200 MP photo (JPEG, plus HEIF if his camera allows) for `fixtures-private/`; remove its location (GPS) data before storing it.
4. PDFs (generated with permissive tools): multipage with text, vector graphics and images; one password-protected; one with existing annotations.
5. SVGs: simple; with text; with a `<script>`; with external `href`s (http and `file://`); with a huge viewBox.
6. Malformed files: truncated JPEG and PNG; a PNG "bomb" (huge declared size, tiny file); a PDF with a corrupt xref; an SVG billion-laughs.
7. PC: install libvips (official Windows build; LGPL; a measurement tool only, not linked). Measure decode time, thumbnail time, and DeepZoom pyramid time and peak memory for the 16320×12240 JPEG.
8. Phone: a small Android benchmark measuring:
   - BitmapRegionDecoder 1024×1024 regions at the top, middle and bottom of the 200 MP JPEG (time and memory);
   - full decode with inSampleSize 8;
   - HEIF decode time and memory (ImageDecoder with a target size, plus a guarded full-size attempt).
9. Write docs/evidence/T0.09.md with the numbers. Append a dated D15 entry to docs/DECISIONS.md.

## Rules

- **Scope:** do only this task. Don't start other tasks, refactor unrelated code, or change requirements you weren't asked to touch.
- **Licenses:** nothing the app ships or links may be GPL, AGPL, SSPL, non-commercial or of unknown license. LGPL is allowed only as a dynamically linked, replaceable library on Windows. The only other exceptions are the documented ones in BUILD_SPECIFICATION §2.5. Check every new dependency's license before adding it. Reading GPL source for ideas is fine; never copy or translate it.
- **Secrets:** never write API keys, pairing secrets, private keys, tokens or signing keys into the repository, logs, evidence files, screenshots or commit messages, and never ask Christian to paste a key or password into this chat. Keys live in Windows Credential Manager or the Android Keystore.
- **Evidence privacy:** before committing any screenshot, recording or log, crop it to the window under test and remove QR codes, IP and MAC addresses, device serial numbers, user names, chat content and notifications. Once T0.03 has built it, take screenshots with `tools/diag-win --screenshot` (Per-Monitor-V2 aware) and record the display scale.
- **Truthfulness:** report something as working only if you ran it and recorded the result. Emulators and simulators do not count for pen, capture, injection, driver, codec or latency checks. Say plainly what you could not test.
- **Spec conflicts:** if the spec is wrong for this hardware or platform, don't quietly change the requirement. Record the evidence in this task's evidence file, propose an alternative, and report it.
- **Versions:** check the official release page before choosing a version; use stable releases only (no previews, betas or release candidates unless this task says so); pin exact versions and record them in docs/TOOLCHAIN.md.

- **Windows code** must be Per-Monitor-V2 DPI aware and use physical pixels for capture, UI Automation and input math.
- **Rust:** edition 2024; rustfmt; clippy with `-D warnings`. - **Git:** follow docs/IMPLEMENTATION_PLAN.md "Automatic phase publishing" and AGENTS.md. Inspect status and preserve unrelated changes.
