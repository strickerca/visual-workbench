## Goal

Measure the three ways the phone and laptop can talk — QUIC over USB tethering, QUIC over Wi-Fi, TCP over adb — on the real devices, measure how fast each recovers, and confirm or change the default carrier order.

## Steps

1. Build a Rust benchmark in `tools/bench/transport` (add to the workspace) with a server (laptop) and a client (an Android executable built with cargo-ndk, run from `/data/local/tmp` via `adb shell`). It supports QUIC (quinn with the `rustls-ring` feature and rustls's `ring` provider — not the default aws-lc-rs — with a throwaway self-signed certificate) and plain TCP. Measure:
   - echo round-trip time for 64 B, 4 KB and 1 MB messages, 1,000 iterations each: p50, p95, p99 and jitter;
   - bulk throughput for 256 MB;
   - QUIC datagram loss and latency for 1 KB datagrams at 120 Hz.
2. Windows Firewall: explain to Christian, then (with his approval of the admin prompt) add temporary inbound allow rules for the executable under test, limited to the local subnet, for example `New-NetFirewallRule -DisplayName "VW dev <task>" -Direction Inbound -Action Allow -Program <full path to the exe> -Protocol UDP -RemoteAddress LocalSubnet -Profile Any` and the same for TCP. If Windows already created a Block rule for that executable, delete it. Never conclude that a carrier fails until a firewall block has been ruled out. Remove these rules at the end of the task.
3. Carrier A — USB tethering: Christian turns it on. Find the PC-side interface (RNDIS/NCM) and bind the server to it. Don't write addresses into the evidence.
4. Carrier B — Wi-Fi: both devices on the same 5 GHz network. Read the band and channel with `netsh wlan show interfaces` (this needs Location allowed; if it is blocked, ask Christian or record them as unknown).
5. Carrier C — adb: `adb reverse tcp:PORT tcp:PORT` for TCP. Confirm and record that UDP cannot pass through it.
6. Recovery baseline (QUALITY-004): measure the time to resume echo after (a) unplugging and replugging USB — Android leaves tethering off after a replug, so record separately the time until Christian turns it back on and the reconnect time after that; (b) turning the phone's Wi-Fi off and on; (c) re-creating `adb reverse` after a replug.
7. Route check with tethering on:
   - Print the default routes with interface metrics (`Get-NetRoute -DestinationPrefix 0.0.0.0/0`), and test whether the PC's internet traffic now goes through the phone.
   - Document a fix (an interface metric change via `Set-NetIPInterface`, admin) and an alternative (no default route on the tether interface). If you apply the fix, revert it with `Set-NetIPInterface -InterfaceIndex <n> -AutomaticMetric Enabled` and confirm the original routes are back.
8. Background throttling: either wrap the client in a minimal APK with a foreground service and compare a foreground run with a background run, or skip this and say why in the evidence.
9. Write the results table in docs/evidence/T0.06.md. Append a dated D7 entry to docs/DECISIONS.md confirming or revising the carrier order, with the numbers.
