## Failure receipts and corrections

- The official minimal libvips build lacks a PPM loader. Initial fixture
  generation failed at that loader; the committed generator uses pinned Pillow
  for encoding. The owned 599270419-byte intermediate was hashed and disposed.
- The initial 200 MP YUV-buffer strategy failed with OutOfMemoryError. Its
  299635200-byte Java input plus two full direct buffers require 898905600 bytes.
  The initial guard reserved system memory but did not account for all buffers
  against the 512 MiB Java limit; the exact throwing allocation was not captured.
  The memory accounting defect is inferred from the source and budget, rather than
  a captured Java allocation stack. The failure, input budgets and original APK/source
  hashes are retained; it was replaced by the small-texture grid strategy.
- One 10-second ADB result poll timed out in a later JPEG run. Its process tree
  and owned device files were cleaned. A fresh model-pinned device-state query
  returned online in 0.3 seconds. The result-poll deadline was increased to 30
  seconds; the subsequent complete run passed. No adb server/device reset or
  OnePlus operation occurred; the original timeout is retained, not erased.
- The first repeat-generation check matched 14 of 18 outputs; four PDFs differed
  because ReportLab used absolute filenames in image XObject IDs. ImageReader now
  keys those IDs by pixel data. Two fresh complete generations verify the corrected
  corpus across different output directories; all JPEG benchmark bytes remain unchanged.

- The first lint run rejected an inherited `WriterBase.close` call as RestrictedApi.
  The caller now uses the public AutoCloseable contract; the final gated build
  runs APK assembly and lint together and has zero lint errors. The final APK
  was reinstalled and the complete S23 measurement/cleanup flow passed again.
