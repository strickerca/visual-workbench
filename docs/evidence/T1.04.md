# T1.04 — Provisional deterministic ink engine

Date: 2026-10-02. The owner's full-continuation instruction authorizes software
work using provisional designs while S23-specific work is deferred. This slice
implements the Rust candidate in D6; it does not finalize that decision or pass
G0/G1. Actual root model/effort: gpt-6-astra / max, matching the task prompt.
Separate agents implemented and reviewed geometry and Android lifecycle code;
the parent serialized all compilation and device tests.

`vw-ink` algorithm 1 provides validated brushes, monotonic cubic Bezier pressure
curves, stabilization, pen/marker/highlighter/vector-eraser geometry, incremental
append/finish/cancel, bounds and hit testing. All transcendental operations use
the pinned libm and geometry is quantized to signed integer 1/256 D-pixel units.
Inputs canonicalize pressure/optional axes to the protobuf f32 representation,
then model in f64. Append validates complete batches before mutation. The API
returns appended contour ranges; finish changes no vertices. Predicted samples
belong to disposable clones and never alter the authoritative saved stroke.

Contours form one NONZERO-filled compound path, painted once. This avoids
over-darkening translucent overlaps. Highlighters use butt caps and outside
join sectors, including explicit collinear, reverse and stationary-width cases.
Round nib tessellation targets at most 1/8 D-pixel sagitta before quantization.
The renderer supplies highlighter multiply blending. Vector-eraser geometry is
for hit testing; editing operations must implement actual object removal.

Limits are explicit: coordinates within plus/minus one billion D pixels,
width at most 4096, one million samples and four million vertices. The comparison
JNI wrapper further limits each stroke to 2048 samples and eight live handles.
Handles are opaque monotonically allocated IDs, never pointers. Invalid/stale
handles and indices fail without dereferencing arbitrary memory. See the crate
and spike READMEs for API/limit details.
