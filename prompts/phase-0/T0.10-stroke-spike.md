## Goal

Decide decision D6 with data: our own deterministic Rust stroke engine versus Jetpack Ink 1.0.0.

## Steps

1. Rust prototype (`tools/stroke-spike`, added to the workspace):
   - Samples in, pressure-width outline out: variable-width offset with round joins and caps; smoothing (One-Euro filter or similar); pressure curve; stabilization.
   - f64 with `libm` only; output polygon quantized to 1/256 px.
   - Incremental API: append samples → new outline segment.
2. Android demo A: front-buffered wet ink (androidx.graphics CanvasFrontBufferedRenderer) plus motion prediction (androidx.input), drawing the Rust geometry through a minimal JNI or UniFFI binding; dry geometry committed at pen-up. Measure:
   - wet-ink latency, using the T0.04 method;
   - wet-to-dry difference: render both and diff, in pixels.
3. Android demo B: Jetpack Ink 1.0.0 (stable, not an alpha) with InProgressStrokes / InProgressStrokesView and a pressure pen brush; same latency measurement.
4. Determinism: run the Rust engine on Windows x64 and on the phone (arm64, through `hil-test rust`) for every fixture trace; the output hashes must match.
5. Feel test with Christian, blind: label the two demos 1 and 2 at random. For each of three stroke types — handwriting, circles, fast lines — he draws about 5 strokes in each demo and says which feels better. Record the preference per stroke type and his comments.
6. Time-box 4 hours of agent effort: try to build google/ink's C++ core for Windows following its README; record the outcome.
7. Apply the D6 rule in DECISIONS.md exactly: "clearly better" means Christian prefers Ink for at least 2 of the 3 stroke types AND Ink's p95 wet-ink latency is not worse than the Rust engine's. Adopt Ink only if it is clearly better AND the Windows build worked within the time box. If Ink is clearly better but the Windows build failed, ask Christian whether to spend up to 2 more days on the Windows build, and record his answer. Append a dated D6 entry with the numbers and his preferences.
