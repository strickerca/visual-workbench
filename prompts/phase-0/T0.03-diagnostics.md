## Goal

Turn every row of the hardware truth table into a verified fact, or mark it explicitly untestable with a reason; build the evidence screenshot tool; set up the measurement method for every performance target.

## Steps

1. Run `powershell -NoProfile -ExecutionPolicy Bypass -File tools/diagnostics/pc-diagnostics.ps1 -OutFile docs/evidence/pc-diagnostics.json`.
   - For Secure Boot, ask Christian to run the one admin command in his steps below.
   - If the Wi-Fi fields come back "unknown", ask Christian to allow Location for this run (his steps below), or mark them untestable.
2. Write a small Rust tool `tools/diag-win` (add it to the workspace), which sets Per-Monitor-V2 DPI awareness as its first action. It prints JSON with:
   - per-monitor physical resolution, effective DPI and scale, orientation, refresh rate and HDR/advanced-color state (DisplayConfig or DXGI);
   - the Media Foundation hardware encoders and decoders found for H.264 and HEVC (MFTEnumEx with the hardware flag).
   It also has `--screenshot <window-title-substring> <out.png>`: capture that one window in physical pixels, crop to it, and print the scale factor. Every later task uses this for evidence screenshots.
3. Run `powershell -NoProfile -ExecutionPolicy Bypass -File tools/diagnostics/phone-diagnostics.ps1 -OutFile docs/evidence/phone-diagnostics.txt`. Extend it if useful: full details of the S Pen input device, display refresh modes, low-latency codec names.
4. Write `docs/evidence/hardware-truth.md`: a table with the same rows as BUILD_SPECIFICATION §2.1 (including Smart App Control), plus anything new you found. Each row gives the value, its status (`verified` with today's date, or `untestable` with the reason), and the command that produced it. Note whether the pen device lists ABS_TILT_X/ABS_TILT_Y, ABS_DISTANCE and ABS_PRESSURE (T0.04 measures behavior in depth).
5. Create `docs/evidence/PERF-template.md` (QUALITY-004). For each of PERF-001 to PERF-009 it states the method, tools, sample count, how p50/p95 are computed, and the environment fields to record. Add the fields for the thermal baseline (phone battery temperature) and the recovery baseline (time to resume after unplug/replug and a Wi-Fi drop) that T0.04 and T0.06 will fill.
6. Update only the `hardware_truth` section of docs/REQUIREMENTS.json with the verified values and statuses.
7. Confirm none of the outputs contains a serial number, computer name, user name or network address. Scan them, and redact if needed.
