# Capture and Air Actions caller composition

This integration starts at accepted main
`6d505416963fb42009921bd3fb8639994e73752a`. Native verification is now published
there after independent review of code `1a3e8e2f` and its 154 reported native
executions. This does not activate its FFI, UI or agent workflow.

The caller composition deliberately selects reviewed source commits from the
preserved caller draft, rather than merging that draft over newer main:

- Capture leaves: `2b03c4e`, `9f9f1ff`, `3b51354`, handoff `e8c1aa5`;
  minimal root registration `a5b683d`; final Desktop caller `490ed8b`, receipt
  `6eba155`.
- Air Actions leaves: `0e5c236`, capacity correction `e143574`; full callers
  `766d1f2`, `cd3c643`; remote-contact correction `cc606a02`, executed receipt
  `46df4c4`. The repair is included and its 17 actual-router scenarios have
  passed in the owner's standalone execution.

Both platform callers match their final reviewed source byte for byte. Root
does not independently revise their owned Main, controllers, dialog or UI files.
Native registration admits region receipts, picker helper requests/responses,
the Windows picker modules and the host picker exports. Cargo gains only the
existing internal `vw-geom` edge. The three earlier root registration files are
rustfmt-normalized. A scoped Clippy allowance retains the single bounded helper
response inline; the picker variant contains metadata, with PNG bytes file-backed.
There is no protocol field or serialization change from that allowance.

Validation is being performed as one coherent phase. Capture/host native tests
pass 137 cases across eight result blocks, including the actual 19 picker and
eight preview/crop cases. The first preflight stopped at root formatting; the
second attempt stopped before tests because native test executables from earlier
phases exhausted the workspace. The failure logs remain in `/tmp`. A bounded
inventory removed only 221 regenerable ELF test executables under
`target/debug/deps`, recovering 17,198,561,536 bytes. Source, libraries, recovery
archives, worktrees and all receipts remain intact. Inventory:
`/tmp/vw-caller-disk-recovery-20261018.json`.

Next validation: strict native Clippy, dependency/license checks, fresh native
libraries, one required binding generation, shared/Desktop/Android JVM tests,
instrumentation source compilation and Android lint. Results will be bound to
the exact composed source. No Windows package, capture/DPI runtime, framework
MotionEvent, native remote ACK, physical S23/S Pen/Bluetooth, GPU presentation,
performance or owner acceptance is established by these software checks.

The existing standalone Android ownership audit compares every changed path
against its lane-only frozen base and therefore refuses this broader integration
branch. Its original receipt remains applicable to the unchanged caller bytes;
the composed batch validates the actual application source instead of weakening
that audit's exclusive-path predicate.
