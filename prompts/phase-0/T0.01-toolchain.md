## Context

Visual Workbench is a personal tool Christian is building. He directs AI coding agents and reviews their work; he does not write code himself, so explain anything you need from him in plain language. The tool pairs his Samsung Galaxy S23 Ultra (S Pen) with his HP Spectre x360 15 laptop (Intel Core i7-1165G7, Intel Iris Xe graphics, 16 GB RAM, 4K display at high DPI scaling, Windows 11 Home 25H2 build 26200, Memory Integrity on). He captures or imports images and app screens, marks them up precisely with the pen, sends them to AI coding agents (Claude Code, Codex) or image models (GPT Image), and checks what comes back. The phone also drives Windows creative apps with pen pressure and can act as a virtual monitor.

Architecture (decided; see docs/DECISIONS.md): one Rust core library (`vw-core`) used by both apps for coordinates, the document model, operations, storage, stroke geometry, exports, protocol and transport; an Android app in Kotlin with Jetpack Compose; a Windows app in Kotlin with Compose Multiplatform desktop; Windows-only services in Rust (`vw-host-win`). The full specification is docs/BUILD_SPECIFICATION.md (v2.0); requirements with measurable acceptance criteria are in docs/REQUIREMENTS.json; the task list, dependencies and status rules are in docs/IMPLEMENTATION_PLAN.md.

## Steps

1. Check free space on C: (`Get-PSDrive C`). If less than 70 GB is free, stop and tell Christian how much is free; don't install anything.
2. Smart App Control: read `HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy`, value `VerifiedAndReputablePolicyState` (0 = off, 1 = on, 2 = evaluation). If it is 1 or 2, stop and explain in plain words that Smart App Control blocks unsigned programs, including everything this project compiles, and ask Christian to turn it off (his steps below). Since the April 2026 Windows update (KB5083769) it can be turned back on later from the same screen. Continue only after he confirms, and record the state before and after.
3. Repository: the root is `C:\dev\visual-workbench` (the unzipped spec package). If it isn't there, ask Christian once where he put it.
   - Run `git --version`; if Git is missing, install it first (`winget install --id Git.Git -e`).
   - Unblock the downloaded files once: `Get-ChildItem C:\dev\visual-workbench -Recurse | Unblock-File`.
   - If the folder isn't a git repository yet: `git init -b main`; add a `.gitignore` (target/, build/, .gradle/, local.properties, *.apk, *.aab, *.jks, *.keystore, *.pfx, *.pvk, fixtures-private/, fixtures/generated/, .idea/, *.iml) and a `.gitattributes` (`* text=auto eol=lf`; `*.bat *.cmd text eol=crlf`; `*.png *.jpg *.jpeg *.webp *.heic *.heif *.avif *.tif *.tiff *.bmp *.pdf *.mp4 *.ttf *.otf *.zip binary`) before the first commit; commit the package as-is on `main` with the message "docs: add v2 spec package"; then create branch `task/T0.01-toolchain`.
4. For each tool in docs/TOOLCHAIN.md, open its official release page and choose the newest stable version compatible with the others. Known constraints: AGP 9.4.x needs Gradle ≥ 9.6 and JDK ≥ 17; Kotlin 2.4.x must match Compose Multiplatform 1.12.x; the JDK must suit both AGP and Compose desktop (21 LTS is the safe choice). Record each URL and the date you checked it.
5. Before any installer runs, and before `sdkmanager --licenses` or `--accept-package-agreements`, tell Christian in one list which license agreements will be accepted on his behalf (Android SDK, Visual Studio Build Tools, the JDK and so on) and get his yes.
6. Install with winget where possible:
   - rustup; a JDK (Microsoft Build of OpenJDK or Eclipse Temurin); Python (current stable 3.x); `just` (optional).
   - Visual Studio Build Tools with the "Desktop development with C++" workload, Windows SDK 10.0.26100 or newer, and the MSVC "Spectre-mitigated libs (Latest)" component for the installed toolset (the T0.08 driver build fails with MSB8040 without it).
7. Install the Android SDK command-line tools only — no Android Studio, no emulator images. With sdkmanager, install platform-tools, `platforms;android-36`, build-tools 36.x, `ndk;30.0.16248370` (or the newest stable LTS if newer) and `cmdline-tools;latest`. Set ANDROID_HOME and PATH for the user.
8. Rust: install stable via rustup; add the targets `aarch64-linux-android` and `x86_64-pc-windows-msvc`; install pinned versions of `cargo-ndk` and `cargo-deny`. Write `rust-toolchain.toml` with the exact version and targets.
9. Set user-level Gradle properties: `org.gradle.jvmargs=-Xmx3g`, `kotlin.daemon.jvmargs=-Xmx2g`, `org.gradle.parallel=false`.
10. Build these hello-worlds under `tools/hello/` and keep them as smoke tests:
    - (a) a Rust binary for `x86_64-pc-windows-msvc` — run it;
    - (b) a Rust `cdylib` built with cargo-ndk for arm64-v8a — check 16 KB alignment with `llvm-objdump -p` (LOAD segments must show `align 2**14`);
    - (c) a minimal Compose Android app (minSdk 29, targetSdk 36) built with the Gradle wrapper, installed on the S23 Ultra with `adb install`, and launched;
    - (d) a minimal Compose Multiplatform desktop window — run it; it must print the display scale it sees (Compose density or the AWT default transform), which must equal Windows' scale setting (for example 2.5), not 1.0. Ask Christian to confirm the text looks sharp.
11. Download, but don't install, the NuGet packages `Microsoft.Windows.WDK.x64`, `Microsoft.Windows.SDK.CPP` and `Microsoft.Windows.SDK.CPP.x64` (the same pinned version) into `C:\dev\cache\nuget` for task T0.08. Record the path and versions.
12. Record peak RAM during the Android and desktop builds, build times, and disk usage after installs. Fill the "Pinned" column of docs/TOOLCHAIN.md. Commit.

## Rules

- **Scope:** do only this task. Don't start other tasks, refactor unrelated code, or change requirements you weren't asked to touch.
- **Licenses:** nothing the app ships or links may be GPL, AGPL, SSPL, non-commercial or of unknown license. LGPL is allowed only as a dynamically linked, replaceable library on Windows. The only other exceptions are the documented ones in BUILD_SPECIFICATION §2.5. Check every new dependency's license before adding it. Reading GPL source for ideas is fine; never copy or translate it.
- **Secrets:** never write API keys, pairing secrets, private keys, tokens or signing keys into the repository, logs, evidence files, screenshots or commit messages, and never ask Christian to paste a key or password into this chat. Keys live in Windows Credential Manager or the Android Keystore.
- **Evidence privacy:** before committing any screenshot, recording or log, crop it to the window under test and remove QR codes, IP and MAC addresses, device serial numbers, user names, chat content and notifications. Once T0.03 has built it, take screenshots with `tools/diag-win --screenshot` (Per-Monitor-V2 aware) and record the display scale.
- **Truthfulness:** report something as working only if you ran it and recorded the result. Emulators and simulators do not count for pen, capture, injection, driver, codec or latency checks. Say plainly what you could not test.
- **Spec conflicts:** if the spec is wrong for this hardware or platform, don't quietly change the requirement. Record the evidence in this task's evidence file, propose an alternative, and report it.
- **Versions:** check the official release page before choosing a version; use stable releases only (no previews, betas or release candidates unless this task says so); pin exact versions and record them in docs/TOOLCHAIN.md.
- **Keep the laptop usable:** it has 16 GB RAM and 4 cores. Cap Gradle at `-Xmx3g`, don't run heavy builds in parallel, and stop processes you start.
- **Scripts:** run PowerShell scripts as `powershell -NoProfile -ExecutionPolicy Bypass -File <script>`; never change the machine-wide execution policy.
- **Windows code** must be Per-Monitor-V2 DPI aware and use physical pixels for capture, UI Automation and input math.
- **Rust:** edition 2024; rustfmt; clippy with `-D warnings`. No `unwrap`, `expect` or `panic` in library code (use `thiserror`). `unsafe` only in FFI and platform modules, each block with a SAFETY comment. Workspace crates use `publish = false` and `license = "LicenseRef-VisualWorkbench-Proprietary"`.
- **Kotlin:** official style; explicit API mode in shared modules; coroutines for async work; nothing blocking on the main thread.
- **Tests** live next to the code. Hardware tests are clearly marked and run through the `hil-test` entry point once it exists; Rust tests run on the phone with `hil-test rust <crate>`.
- **Git:** follow docs/IMPLEMENTATION_PLAN.md "Automatic phase publishing" and AGENTS.md. Inspect status and preserve unrelated changes. Start from main with validated dependency work integrated; use the task branch convention and conventional local commits. Local commits/completed dependency integration and phase-end commit/push to origin/main are already owner-authorized; do not request Git approval again. Push automatically at numbered phase conclusions, not after every task. Scan the exact staged bytes, exclude secrets/local artifacts/verification images, use normal non-force pushes and verify remote SHA parity. Product gate confirmation remains separate. Use worktrees for parallel tasks and take turns on the shared phone.
- **Christian's help:** when you need him (physical pen actions, approving an admin prompt, installing an app, entering a key, changing a phone setting), batch the requests into numbered, plain-language steps and wait for him to confirm.
