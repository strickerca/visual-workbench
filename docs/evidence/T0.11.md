## Implemented behavior

`tools/ai-spike` implements crop expansion, aspect growth with preserve-only edge
padding, valid size selection, area-filtered masks, normalized premultiplied
Lanczos3 pixels, RGB ICC conversion, feathered compositing and exact exterior
proof. EXIF orientation is applied once before interpreting document coordinates.
Encoded originals are never overwritten. PNG/JPEG8 inputs are bounded to 20 MP and
16,384 pixels per edge; 16-bit and unsupported profiles fail explicitly in this
measurement CLI. The app-level implementation remains a separate Phase2 task.

A Windows WinHTTP adapter prepares HTTPS requests and reads only the configured
Credential Manager entry after explicit confirmation and a reviewed cost estimate.
The fixed, exclusively locked local ledger reserves the estimate before credential
access and synchronizes a single-use attempt marker before any possible POST.
Uncertain network/billing outcomes stay reserved and block further sends; there is
no retry, redirect, environment-key fallback or live ledger path override. The $2
spike guard reserves estimates; it cannot guarantee a provider-enforced billing
ceiling. Missing estimates block sending by default. None of these tests read a
credential or called the live adapter with a valid send authorization.
