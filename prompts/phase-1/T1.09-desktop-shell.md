## Goal

The PC window that shows the shared document at its own view, lets Christian edit it with the mouse, pairs with the phone, and can be driven entirely from the keyboard.

## Steps

1. Compose Multiplatform desktop app, laid out per §4.17:
   - canvas in the center;
   - left panel for layers and objects (placeholder);
   - right instruction panel (placeholder labelled "available in Phase 2");
   - bottom transfer shelf (placeholder, labelled);
   - window modes: windowed, maximized, borderless fullscreen (F11), with window state persisted.
2. DPI: the window must report the Windows display scale (density equal to the Windows scale, for example 2.5). Take evidence screenshots with `tools/diag-win --screenshot`; text and 1-px lines must be crisp at 100% zoom. If a second monitor is available, test moving between monitors.
3. Canvas:
   - rendering from core render lists;
   - independent camera: mouse (drag and wheel), touchpad pinch and two-finger scroll where the JVM delivers them, and Ctrl+wheel zoom. On the touchscreen, one-finger pan only — Compose desktop gets no multi-touch from AWT on Windows; record this limit;
   - optional outline of the peer's viewport;
   - follow-peer and match-view commands, off by default.
4. PC editing with the mouse: select, move and resize objects with handles; change color and width; delete; undo/redo; arrow keys nudge the selection 1 D-pixel (Shift = 10). Each edit is one undoable transaction. Handle drags and slider moves are gestures the core can stream to the phone (T1.10 wires the streaming).
5. Status chips using the fixed status words of §4.17 (the sync and export states are exercised in T1.10 and T1.11).
6. Keyboard shortcuts for every command, shown in menus and tooltips (the PC part of UX-004; the phone part is in docs/evidence/T1.08b.md).
7. Project location per §4.5: if Documents is synced by OneDrive or another cloud client, default to `%LOCALAPPDATA%\Visual Workbench\Projects` and tell the user. Record which applies without writing the user name into the evidence.
8. PC pairing: add session and pairing calls to vw-ffi; show the QR code (permissively licensed QR library) and the 8-digit code fallback; list paired devices; revoke. Verify against the `tools/pair-cli` phone binary — the phone app's pairing screen comes in T1.10. This is the first time the desktop app accepts inbound connections.
9. Windows Firewall: explain to Christian, then (with his approval of the admin prompt) add temporary inbound allow rules for the executable under test, limited to the local subnet, for example `New-NetFirewallRule -DisplayName "VW dev <task>" -Direction Inbound -Action Allow -Program <full path to the exe> -Protocol UDP -RemoteAddress LocalSubnet -Profile Any` and the same for TCP. If Windows already created a Block rule for that executable, delete it. Never conclude that a carrier fails until a firewall block has been ruled out. Remove the rules at the end of the task.
10. Measure startup time.
